# 20 README translation checks by section

## Goal

讓 README 結構檢查能辨識跨章節的段落錯置，避免整份文件的總數相同就通過。已在暫存副本重現：將 `README.ja.md` 的「Skills CLI でインストールした既存のスキルを更新します：」從「インストールと更新（Skills CLI）」移到「ライセンス」，現有 `make readme-sync` 仍回傳 0。這次交付以明確的跨語言章節對應及自動回歸檢查補上這個盲點；檢查只供本 repository 使用。

## Out of Scope

- 翻譯語意與品質、同章節內的段落順序，以及結構訊號完全相同的文字替換或互換。
- 重寫三份 README 的產品說明、安裝指令或翻譯內容；只允許同步更新三份 README 的驗證說明。
- 修改 `plugin/`、發佈給採用端的工具、Warrant 規則、網站功能、release 或 CI workflow。
- 新增第三方套件依賴、付費模型評測，或保證任意 Markdown 語法的通用解析能力。
- 修改其他 Story 或既有無關變更，包括 `site/package-lock.json` 與 `specs/stories/19-site-cache-dependency-audit.md`。

## Acceptance Criteria

1. `make readme-sync` 對最終三份 README 回傳 0。檢查對每個 `##` 章節分別比較正文段落數、清單項目數、程式碼區塊內容與連結目標，而非僅比較整份文件總數；第一個 `##` 之前的內容仍受到原有結構檢查保護。沿用 `Makefile` 現有段落、清單與連結排除規則，不藉此改寫既有判定標準。
2. 實作提供單一、明確的英／繁中／日章節標題對應，不能只按第幾個章節配對，也不能依靠模型判斷翻譯。各文件的章節須恰好匹配此對應一次，且對應後的順序一致。在隔離副本分別製造缺少、重複、未知標題，以及交換兩個完整章節的案例，檢查均須非 0，並指出檔名與相關章節。程式碼區塊內的 `##` 文字不能被當成文件章節；以三份內容一致的測試副本驗證此情況仍通過。
3. 自動回歸案例重現 Goal 中的日文段落搬移：變動前副本通過，搬移後非 0，錯誤輸出至少包含 `README.ja.md`、來源或目的章節及 `paragraphs` 訊號。案例保留全文件段落總數不變，並呼叫實際供 `make readme-sync` 使用的檢查路徑，不在測試內重寫比較邏輯。
4. 另一個自動回歸案例在繁中副本中將「文件」章節的一個完整清單項目移到「授權」章節，保持全文件清單總數不變；變動後須非 0，輸出包含 `README.zh-TW.md`、相關章節與清單訊號。正常三語副本、僅改變普通正文措辭而保持結構的副本均須通過。
5. 既有保護仍有效：在獨立副本分別刪除章節標題、刪除正文段落、刪除清單項目、修改程式碼區塊中的指令，以及新增未同步的連結目標，均須非 0。保留 README 互連與錨點的既有排除行為，並以正例證明。測試只操作隔離副本，成功或失敗均不得改動實際 README。
6. 提供 `make readme-sync-test` 執行上述正反例，全部符合預期時回傳 0，任何預期不符時非 0；`make verify` 納入此 target。檢查與測試只依賴 repository 現有驗證環境提供的工具，不新增第三方套件。三份 README 的驗證說明同步交代逐章節檢查及不檢查翻譯語意的限制。
7. 最終未提交工作樹執行 `make readme-sync-test`、`make readme-sync` 與 `make verify`，全部回傳 0。完成報告列出實際執行的命令與結果；本 Story 不要求 commit、push 或執行遠端 CI 才能取得交付證據。
